# Raven Zero 框架设计

设计访谈的范围与行为选择及完整首版规格均已确认。完整规格见 [v1 规格](v1-spec.md)，已锁定的技术框架见 [技术选型](technology-stack.md)；按用户要求，暂不开始实现。

客户端形态已确认：用户显式启动持续接单管理程序，框架主动控制每任务专用 Agent 会话，原生界面按需附着。服务端与客户端通过 HTTP API 通信，客户端长轮询领取任务；任务及工作流使用 JSON 定义与对应 TypeScript 类型。

## 已确认范围

- 使用 TypeScript 实现可集成到其他项目的模块化框架。
- 服务端负责 AI 工作任务的编排与调度，下发给客户端，并接收执行结果。
- 客户端连接 Agent 完成具体工作，通过 Agent 适配器支持不同工具。
- 可嵌入模块作为核心，同时提供使用同一套模块的独立运行程序，见 [ADR 0001](../adr/0001-embeddable-framework.md)。
- 首版客户端面向个人开发机器；后续也需要支持由集成方管理的工作节点。
- 首版编排使用预定义工作流，支持任务依赖与并行分支，不包含根据执行结果动态生成任务的规划能力。
- 首版按客户端在线状态、Agent 能力和可用执行名额即时调度任务，不包含定时执行和周期任务。
- 首个真实 Agent 适配器为 Codex，同时提供模拟适配器验证框架流程；后续用第二个真实适配器检验接口通用性。
- 服务端提供工作区初始化方式，例如下载文件或执行初始化命令。客户端在全局工作区目录下创建任务工作区，初始化后在其中执行工作，见 [ADR 0002](../adr/0002-server-defined-workspace-initialization.md)。
- 任务自行指定完成条件；首版代码任务的交付方式为 Git 提交并推送分支，见 [ADR 0004](../adr/0004-git-branch-delivery.md)。
- 服务端面向一个使用者连接其多台个人开发机器的远端使用模式；验证时允许服务端和客户端都在本机启动。
- 一个任务是一次交给 Agent 的完整工作单元，内部可以包含多个步骤；工作流组织多个这样的任务。
- 完成条件包含自然语言要求与可执行检查。客户端执行检查并报告证据；业务语义是否正确仍需使用者审查，不能仅由可执行检查通过推定。
- 用户配置客户端时信任指定服务端，之后自动初始化任务；该服务端及有权提交任务的人具有向客户端下发初始化命令的权限。
- 首版支持 Agent 执行中的人工交互：暂停、展示问题或审批请求、接收用户回答后继续。
- 任务可以选择客户端已注册的交付组件及参数，核心不包含固定的 Git 流程；首版提供 `git-branch`。调度时匹配客户端所需的 Agent 与交付组件能力，见 [ADR 0003](../adr/0003-task-selected-delivery.md) 与 [ADR 0004](../adr/0004-git-branch-delivery.md)。
- 完成检查分为交付前检查与交付后检查。首版代码任务通过检查并提交、推送分支后结束，不要求创建 PR 或 MR。
- 第二个验收场景为生成指定格式的本地报告：服务端提供输入文件，Agent 生成报告，客户端检查文件及格式并上报结果，不使用 Git 交付组件。
- 任务上报结构化输出和文件产物，由服务端保存。后续任务可以引用前序输出作为初始化参数并下载前序文件；Git 成果通过提交或分支引用传递，不共享任务工作区，见 [ADR 0005](../adr/0005-server-mediated-task-artifacts.md)。
- 首版采用单服务端实例，服务端使用 MySQL 持久化任务、工作流和结果，客户端使用 SQLite 保存本地执行记录；存储能力通过模块接口接入，见 [ADR 0012](../adr/0012-server-mysql-client-sqlite.md)。
- Agent 执行中的问答与本地权限审批由客户端处理。首版允许 Codex 原生终端界面，Codex App 接入另行验证，见 [本地交互调查](codex-local-interaction.md)。
- 首版 Git 交付仅使用客户端已有 Git 凭证，不限制 GitHub 或 GitLab，不要求平台 API 凭证或 `gh`。
- 每个客户端配置独立、可撤销的访问令牌；服务端管理 API 使用单独的管理令牌。客户端主动连接服务端，不要求开发机器开放入站端口。跨机器部署使用 HTTPS，本机验证允许 HTTP，首版不引入用户账户系统。
- 网络断开时，客户端继续已有任务并保存结果，重连后补报；服务端不自动把同一任务分配到另一台机器。
- 客户端或 Agent 意外退出后保留工作区和执行记录，由用户选择继续或重试；交付恢复不默认重新运行 Agent，见 [ADR 0007](../adr/0007-local-interaction-and-explicit-recovery.md)。
- 取消请求在收到客户端停止确认后才算执行已停止；客户端离线时显示取消待确认。
- 工作流中某个任务失败时阻止其后继任务，其他无依赖分支继续并保留成果，最终工作流标记失败。显式重试成功后可以继续推进被阻止的任务。
- Git 任务指定远端仓库与基准引用，框架为任务执行实例生成稳定、唯一的分支名。交付重试复用已记录提交，禁止强推；远端冲突报告交付失败。
- 没有文件改动时不制造空提交，报告无改动；是否接受由任务完成条件决定。
- 首版使用 Node.js 24，客户端支持 macOS 与 Linux，服务端支持 Linux 与本机启动；Windows 原生支持留待后续。
- 首版保留任务工作区、执行记录与服务端文件产物，提供显式清理能力，不自动删除失败现场；自动过期与容量管理留待后续。
- 用户开启一次接单入口后自动执行任务；每个任务使用专用 Agent 工作会话，并通过 Agent 原生界面交互。排除 Agent 调用框架工具领取和推进任务的方案，见 [ADR 0008](../adr/0008-framework-controlled-dedicated-sessions.md)。
- 首版采用方案 A：接单管理程序持续运行，原生界面按需附着；由用户显式启动，不安装系统常驻服务，见 [ADR 0009](../adr/0009-client-manager-independent-ui.md)。
- 原生界面尚未附着时可以执行无需交互的工作；审批或问答留在对应会话等待用户，不自动批准。
- Agent 工作阶段结束后自动收尾，将本版成果发布到受保护的独立交付工作区，再检查、交付并上报；Agent 后续写入不能修改本版成果。原任务工作区和会话身份用于显式恢复，新版本不覆盖旧成果，见 [ADR 0020](../adr/0020-protected-delivery-workspace.md)。不保留无结束边界的自由多轮交互。
- 使用 HTTP API，客户端长轮询领取任务，心跳、进度、结果与文件产物通过 HTTP 上报，断线主动重连。CLI 提供提交、状态查询、日志、取消和请求恢复，集成方可以直接使用相同模块或 API。
- 客户端提供准确的原生会话附着入口；审批与问答回答不经过服务端。
- 任务与工作流使用可序列化 JSON 定义及对应 TypeScript 类型，通过嵌入模块、HTTP API 或 CLI 提交。
- 任务声明工作要求、Agent 能力要求、按顺序执行的初始化步骤、可选交付组件与参数、交付前后检查，以及结构化输出与文件产物。工作流声明任务依赖与前序输出引用。
- 首版通用检查提供命令成功、文件存在；报告格式通过任务指定的命令检查。Git 交付组件额外核实远端提交。
- 等待本地交互时仍占用执行名额，服务端只记录等待状态，问题、审批内容与回答留在客户端。默认等待用户，不自动批准。
- 任务可指定执行期限，人工等待计入期限；超期请求停止，在收到实际停止确认后记录为已停止。

## 首版验收场景

给定代码仓库和需求，以及服务端提供的工作区初始化方式，客户端创建并初始化任务工作区，调用 Codex 修改代码、运行测试，交付前检查通过后由 `git-branch` 组件提交并推送分支，完成交付后检查，将结果报告给服务端。完成条件由任务指定，不要求创建 PR 或 MR。

随后用生成指定格式本地报告的任务验证框架的通用性，检查报告文件及格式并上报结果，不使用 Git 交付组件。

## 实现时必须验证的事实

- 目标 Codex 版本的多客户端订阅、活动任务附着与原生终端审批、问答行为。
- Node.js 24 的 SQLite 驱动兼容性；当前本机版本的内置 `node:sqlite` 为 release candidate，可替换存储接口应保持独立于具体驱动。
