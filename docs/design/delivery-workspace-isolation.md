# 交付工作区隔离契约

2026-10-07 用户授权按“确定边界、最小原型、拆分实现任务”推进。本轮采用[ADR 0020](../adr/0020-protected-delivery-workspace.md)的工作区分离方案；生产代码尚未实现。

## 边界与入口

- 任务工作区用于初始化与 Agent 工作；原生 CLI 仍附着准确的专用会话。初版复用个人 `CODEX_HOME` 的决定保持有效。
- 交付工作区保存任务执行实例某一版实际捕获的成果。交付前检查、可选交付、交付后检查与文件产物上报使用该版本；客户端的受控检查与 Git 操作可以按各自阶段写入，Agent 不能写入。
- 交付目录、执行记录及必要的可变祖先路径，从任务执行前就受框架控制的外层执行边界保护。任务子进程继承约束；原生批准、会话沙箱切换或服务端退出不解除约束。只有路径不同、目录名称随机或改变权限位都不构成这个契约。
- 回合完成仅是进入收尾的候选信号。客户端关闭该专用会话的输入入口、核对活动回合和待答请求、停止专用端点并确认退出，再发布成果。尚未解决的问答或审批不自动批准，也不发布成果。
- 外层边界未生效、权限扩大后无法核对、存在绕过该边界的任务执行入口，或成果发布不完整时，保存现场并进入待核对状态，不运行检查或交付。不得静默回退到普通目录副本。

```text
任务工作区＋专用会话（Agent 可写）
  → 收尾、确认专用端点退出
  → 捕获本版成果、核验并发布到交付工作区（Agent 不可写）
  → 交付前检查 → 可选交付 → 交付后检查 → 保存并上报本版结果

显式恢复：核对真实状态 → 原会话＋原任务工作区继续工作 → 发布下一版
```

## 成果发布与恢复

执行记录关联任务执行实例、原工作区、准确会话身份、成果版本、交付工作区和检查、交付进度。未完成发布的目录不作为可恢复的有效成果；重启先核对已保存版本及内容，再继续其检查或交付，不默认重跑 Agent。

捕获过程不承诺活动源目录的原子时间点一致性；检查针对发布后实际保存的内容。生产发布必须安全枚举和读取文件，保留所需可执行位、打断与原工作区的硬链接，并禁止输出路径或链接将检查与产物读取导回活动源目录或外部目标。原型的 copytree 只用于受控夹具，不能直接作为并发链接替换下的生产实现。

Git 交付元数据由客户端管理，不复用指向 Agent 工作区的 `.git` 文件或共享可写 Git 元数据。交付恢复复用已记录提交；成果版本变化必须重新检查，不能拿第一版的检查结果交付第二版。没有 Git 交付的报告任务也使用相同成果边界。

显式恢复先核对旧会话和真实执行状态，保留原工作区及会话身份；下一版使用新的交付工作区。恢复不覆盖旧版成果、提交身份或已上报结果，也不自动吸收旧工作区的晚到写入到已发布版本。

交付隔离与停止确认分开：后台进程可能仍能写原工作区；不能因此报告取消、超期或全部任务进程已停止。跨恢复代际的旧进程处理、结果去重及崩溃时的发布核对仍由正式实现验收。

## 真实实验结果

原型保存在 `codex/prototype-delivery-isolation` 分支的 `prototypes/delivery_isolation/`，固定提交为 [`edbd170`](https://github.com/Vamdawn/raven-zero/tree/edbd170208dc19f306bcf8bbbcf0d461596a9021/prototypes/delivery_isolation)。代码、真实协议及文件结果、失败探索与单文件状态演练均保留；实现任务见后续[实施计划](implementation-plan.md)。

| 实验 | 结果 |
| --- | --- |
| 仅复制目录，无外层限制 | 九种写入路径均成功，成果与执行记录被修改；反例成立 |
| macOS 外层 Seatbelt 限制 | 绝对、相对、符号链接、硬链接、替换、删除、chmod、受控根目录改名与记录写入均被拒绝；旧源文件句柄仍可写；成果内容不变 |
| Linux Docker 只读交付与记录挂载 | 对应容器内访问被拒绝；源工作区句柄可写；没有验证 Linux Codex 原生交互 |
| 本版检查与 Git 交付 | 两个平台的文件实验执行成果副本中的检查命令、向本地 bare remote 推送 v1；生成 v2 后，远端 v1 提交身份与内容仍保持不变 |
| macOS 真实 Codex 0.155.1 | 原生回答 Blue、普通命令、原生批准启动后台夹具、原生批准晚到写入请求；最后一项仍被外层拒绝；关闭服务端后后台九种写入路径仍被拒绝 |
| Codex 重启恢复 | 重启专用服务端后恢复同一 thread ID 和原工作区，真实执行修改并发布 v2；v1 内容保持不变 |
| 个人 Home 影响 | 本轮测试使用独立临时 Home，校验 initialize 返回的 codexHome；三个实际创建的测试 thread ID 均未进入个人数据库，暂存认证已删除；未核验 App UI 分组 |

macOS 的第一次真实试验发现外层与 Codex 内层 Seatbelt 嵌套使正常命令报 `sandbox_apply: Operation not permitted`。修正后，普通工作及恢复使用目标版本生成协议中的 `externalSandbox`；原生审批夹具仍由 CLI 处理。实验 deny 策略只验证指定成果与记录的保护，不等于完整生产权限策略。

## 剩余验收门槛

2026-10-08 用户将 Linux 验证移到后续。以下为初版 macOS 门槛；此前 Linux 容器结果保留为历史证据，不作为初版支持承诺。Docker 只是此前实验载体，未锁定为正式客户端依赖。

- macOS 正式执行边界、可变祖先保护与启动自检，以及 Codex 原生路径和嵌入场景。
- 复用个人 Home 时的配置、权限与原生 CLI 切换行为；测试 Home 成功不能替代这一组合的验收。
- 待答请求、活动命令、原生重连与收尾竞争；SIGTERM 超时后确认退出、取消与超期的真实停止语义。
- 并发链接替换、动态文件树、发布中断、版本校验、Git 元数据与源目录分离；任务检查产生的文件及上报文件的版本归属。
- 宿主外部执行服务、MCP、特权命令和 IPC 转交：必须受同等边界约束，否则不纳入已隔离路径。

[官方沙箱说明](https://learn.chatgpt.com/docs/sandboxing)区分技术执行边界与审批策略；实际接入行为以本机生成协议及真实探针为准。本轮只通过设计问题的最小验证，[Issue #1](https://github.com/Vamdawn/raven-zero/issues/1)继续跟踪正式适配器验收，不能据此宣布首版兼容全部通过。
