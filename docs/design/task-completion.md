# 任务完成与交付职责讨论

交付职责方案已确认，见 [ADR 0003](../adr/0003-task-selected-delivery.md)。首版交付方式调整见 [ADR 0004](../adr/0004-git-branch-delivery.md)，恢复原则见 [ADR 0007](../adr/0007-local-interaction-and-explicit-recovery.md)。

## 已确认前提

- Raven Zero 是通用的 AI 工作任务框架；首版验收场景是代码任务。
- 任务自行指定完成条件，包含自然语言要求与可执行检查。
- 客户端执行检查并报告证据。
- 首版代码任务提交并推送分支，使用客户端已有 Git 凭证；不要求创建 PR 或 MR，见 [ADR 0004](../adr/0004-git-branch-delivery.md)。

## 需要区分的概念

- 工作目标：希望 Agent 完成什么，例如实现一个功能或生成一份文档。
- 交付动作：让工作成果到达指定位置，例如提交并推送分支。
- 完成检查：验证声明的条件，例如测试命令成功、输出文件存在或指定远端分支包含预期提交。

任务指定完成条件，并不意味着交付动作必须由 Agent 执行；交付动作成功也不能替代其他完成检查。

## 候选方案

| 方案 | 优点 | 代价 |
| --- | --- | --- |
| Agent 执行全部工作与交付 | 对新任务类型要求较少，能直接使用 Agent 的工具能力 | 需要检查实际交付证据；重复执行可能重复产生外部副作用 |
| 客户端固定执行 Git 提交与推送 | 代码任务的交付步骤明确，容易检查与管理失败 | Git 交付不适用于所有任务，不能成为通用核心的固定流程 |
| 任务选择可选的客户端交付组件，也允许 Agent 自行交付 | 确定性步骤可由程序执行，不同任务可采用不同交付方式 | 需要组件注册、调度时的能力匹配，以及各组件对重复执行的处理 |

## 已确认方案

通用核心协调任务生命周期，不固定包含 Git 或 PR 动作。任务可选择一个由客户端预先注册的交付组件；未选择时，由 Agent 完成任务要求的工作与交付。无论交付主体是谁，客户端都按任务声明的检查报告结果与证据。

首版提供 `git-branch` 交付组件与相关检查能力。交付组件通过服务端可识别的名称和参数引用，不由服务端下发动态 JavaScript 实现。

代码任务中，Agent 修改代码；交付组件执行提交与推送。测试等交付前检查通过后再执行交付，之后核实远端分支与提交。其他任务可以没有额外交付动作，例如只要求生成指定文件。

## 已确认交付与恢复规则

- 任务指定远端仓库和基准引用，框架为任务执行实例生成稳定、唯一的分支名。
- 交付重试复用已记录的提交，不重复生成提交，不默认重新运行 Agent。
- 禁止强制推送；远端冲突报告为交付失败。
- 没有文件改动时不制造空提交，报告无改动；是否接受由任务完成条件决定。

## 首版结束边界与通用性验证

代码任务在交付前检查通过、Git 提交并推送分支、完成交付后检查时结束，不要求创建 PR 或 MR。

第二个验收场景是生成指定格式的本地报告：服务端提供输入文件，Agent 生成报告，客户端检查文件及格式，上报结果。该任务无需 Git 交付组件。
