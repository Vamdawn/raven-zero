# Raven Zero 首版规格

本规格已于 2026-10-07 经用户确认，作为后续实现依据。按用户要求，本次仅提交设计文档，暂不开始实现。

后续技术选型阶段已确认服务端使用 MySQL 8.4 LTS、客户端使用 SQLite，并锁定 HTTP、契约、Agent 接入与工程工具，见 [完整技术栈](technology-stack.md)。本规格同步数据库调整；技术选型已确认，真实兼容性仍待验证，暂不开始实现。

## 产品与运行形态

使用 TypeScript 与 Node.js 24，交付可嵌入模块和使用同一套模块的独立服务端、客户端与 CLI 入口。首版面向一个使用者管理自己的多台个人开发机器，服务端为单实例，客户端支持 macOS、Linux；本机可以同时启动服务端和客户端完成验证。

用户显式开启接单管理程序，它在运行期间自动领取并执行任务，不安装系统常驻服务。客户端先创建并初始化任务工作区，再由框架主动启动每任务专用 Agent 工作会话。原生界面按需附着到准确的任务会话；无界面时无需交互的工作继续，审批与问答则等待用户。

首个真实适配器为 Codex，首版原生交互使用 Codex CLI；Codex App 接入单独验证，不能列为当前已保证能力。同时提供模拟 Agent 适配器验证框架行为，后续用第二个真实 Agent 验证接口通用性。

已确认的默认值：客户端默认一个执行名额，可配置多个。并行执行时每个任务仍有独立工作区、Agent 会话与附着入口；等待本地交互的任务不释放名额。

## 模块安排

以下名称表示职责划分，不要求每个内部步骤单独成为公开模块。

| 模块 | 对外职责 | 内部实现 |
| --- | --- | --- |
| 核心契约 | 任务、工作流、执行实例、能力、结果和产物的 TypeScript 类型及 JSON 校验 | 定义校验、依赖检查和显式前序输出引用，不引入通用脚本语言 |
| 服务端 | 提交和查询工作流、分配任务、接收进度与结果、取消和恢复请求 | 依赖推进、能力及名额匹配、执行归属、去重与失败传播；提供 HTTP 入口 |
| 客户端 | 开启接单、执行任务、查询本地进度、恢复与停止；可嵌入既有应用 | 长轮询、工作区初始化、执行记录、名额、完成检查、交付、补报与原生附着指引 |
| Agent 适配器 | 在指定工作区开始、观察、核对和停止专用 Agent 工作会话 | Codex 协议、会话标识、原生界面连接、交互状态与目标版本差异；模拟适配器使用相同契约 |
| Git 交付 | 任务选择 `git-branch` 后提交、推送并提供交付证据 | 稳定分支名称、提交记录、推送检查、冲突与阶段恢复，使用客户端已有 Git 凭证 |
| 存储 | 服务端状态和文件产物存储、本地执行记录持久化 | 服务端 MySQL、客户端 SQLite 与本地文件；接口使集成方能够替换存储实现 |
| CLI | 独立启动、提交定义、查询状态与日志、取消、恢复、清理与附着指引 | 调用相同模块或 HTTP API，不重复实现调度和执行规则 |

服务端不执行个人机器上的工作区命令。客户端不拥有全局工作流编排。通用核心不固定包含 Git 交付，Agent 适配器不承担检查、Git 交付或服务端调度。

## 定义与任务提交

任务和工作流均可序列化为 JSON，并提供对应 TypeScript 类型。支持嵌入模块、HTTP API 和 CLI 提交。

任务声明：

- Agent 工作要求及能力要求。
- 初始化步骤：按顺序下载文件、执行命令，在任务工作区中准备输入与环境。
- 可选交付组件名称与参数，首版真实组件为 `git-branch`。
- 交付前与交付后的完成检查。
- 结构化输出和要上报的文件产物。
- 可选执行期限，人工等待计入期限。

工作流声明预定义任务及依赖关系，支持并行分支；后续任务可以显式引用前序结构化输出作为初始化参数，并下载前序文件。任务工作区不共享，Git 成果通过提交或分支引用传递。

首版通用检查为命令成功和文件存在；报告格式由任务指定的检查命令验证。完成要求由任务拥有，框架不把所有任务绑定到同一种交付物。检查通过不能独立证明全部自然语言业务要求正确。

## 服务端通信与身份

客户端主动连接 HTTP API，长轮询领取任务；心跳、进度、结果和文件产物使用 HTTP 上报。跨机器部署通过 HTTPS 入口，本机验证允许 HTTP，不要求开发机器开放入站端口。

每个客户端使用独立、可撤销的令牌；管理 API 使用单独管理令牌，首版不引入用户账户系统。用户配置客户端时信任指定服务端，该服务端及有权提交任务的人可以下发初始化命令。

服务端记录任务与交互等待状态；本地问题、审批内容及回答不经服务端处理。CLI 与集成方使用相同管理能力，不增加服务端 Web 界面。

## 执行生命周期

```text
依赖满足、等待分配
  → 按在线状态、能力和可用名额分配并记录归属
  → 客户端创建、初始化任务工作区
  → 启动专用 Agent 工作会话
  → 执行；需要问答或审批时等待本地原生交互
  → 工作阶段结束、隔离后续写入
  → 交付前检查
  → 可选交付
  → 交付后检查
  → 保存结果与产物、上报
  → 服务端确认接收并推进后继任务
```

等待人工交互时继续占用执行名额，不自动批准。原生界面关闭、Agent 一轮回答结束、本地检查通过和服务端确认收到结果是不同事实，不得混为任务成功。

Agent 工作阶段自动收尾，不保留无结束边界的自由多轮会话；工作结束与后续写入隔离必须由适配器建立可靠契约。继续修改通过显式恢复或后续任务处理。

本地结果先保存再上报。上报或确认丢失时补报同一结果，不因此重新运行 Agent 或重新生成 Git 提交。服务端只有收到所需结果与产物后，才能按成功状态推进依赖任务。

## 失败、取消与恢复

- 某个任务失败时阻止其后继任务，没有依赖它的其他分支继续并保留成果，工作流最终标记失败。显式重试成功后可以继续推进后继任务。
- 检查失败保存证据并按失败处理，不自动引入无限 AI 修复循环。
- 网络断开时已有任务继续，本地保存进度与结果，重连补报；服务端不自动把同一任务转派给其他机器。
- 客户端或 Agent 意外退出后保留工作区、进度与会话身份，由用户选择继续或重试。恢复先核对真实执行状态，不能依据最新会话或目录相同猜测。
- 交付恢复从已记录进度继续，不默认重新运行 Agent。
- 取消在客户端确认实际停止后才算执行已停止；离线时保留取消待确认。超期遵守同一停止确认规则。
- 停止接新任务、等待已有任务后退出，与请求停止已有执行是不同操作；等待人工回答时应显示原因。未确认停止的执行保留待核对记录。
- 保留任务工作区、执行记录和服务端文件产物，提供显式清理能力；首版不自动删除失败现场，不提供自动过期或容量管理。

## Git 交付

任务指定远端仓库与基准引用。框架为任务执行实例生成稳定、唯一的分支名，交付时保存提交身份；恢复复用该提交，不重复生成提交。

使用客户端已有 Git 凭证，不依赖 GitHub、GitLab 平台 API 或 `gh`。禁止强推，远端冲突报告为交付失败。无文件改动时不制造空提交，报告无改动，是否接受由任务完成条件决定。

代码任务在交付前检查通过、提交并推送分支、交付后检查通过后结束。交付证据包含远端、分支和提交身份，不要求创建 PR 或 MR。

## 验收清单

| 场景 | 必须可观察的结果 |
| --- | --- |
| 代码任务 | 从服务端初始化要求创建独立工作区，Agent 改代码，检查通过，Git 交付后远端分支包含预期提交，服务端收到证据 |
| 报告任务 | 输入文件进入独立工作区，Agent 生成指定格式报告，文件及格式检查通过，产物上报；不调用 Git 交付 |
| 本地人工交互 | 无界面时任务能够开始；审批或问答出现后等待、占用名额，附着准确的原生会话后回答并继续；服务端不接收回答内容 |
| 自动收尾 | 工作阶段结束后不会在检查与交付期间由同一会话继续修改工作区；无需用户逐任务手动触发交付 |
| 工作流分支 | 依赖任务等待前序成功，独立分支可分配到可用名额；失败仅阻断后继，其他分支成果保留 |
| 跨任务产物 | 后续任务在独立工作区引用前序结构化输出、下载前序文件，不依赖前序机器的本地目录 |
| 客户端断网 | 已有任务继续；重连后补报，未重复启动任务或交付，服务端未将失联执行自动转派 |
| 服务端重启 | 任务、工作流、归属与已接收结果持久保存，重启后能查询并继续接受进度和结果 |
| 进程意外退出 | 保留任务工作区和执行记录，能核对原会话；显式恢复不误提交新的重复工作 |
| 交付部分失败 | 已提交或已推送的进度保留，恢复复用提交；推送冲突不强制覆盖 |
| 取消或执行超期 | 发送停止请求与确认停止可区分；离线取消保持待确认，未把原生界面退出当作停止确认 |
| 认证与能力匹配 | 未获授权不能提交或更新执行；任务不会分配给缺少所需 Agent、交付能力或空闲名额的客户端 |
| 嵌入使用 | 集成方无需启动独立框架产品进程，也能调用相同服务端与本地执行模块 |

框架行为以模拟 Agent、真实临时文件、服务端 MySQL、客户端 SQLite 与本地 Git bare remote 验证；MySQL 集成行为不以 SQLite 测试替代。Codex 兼容性另以真实目标版本验证，不能用模拟结果替代原生交互验收。

## 实现顺序与事实验证

1. 先验证目标 Codex 版本的原生终端附着、问答与审批、多连接观察、界面断开及自动收尾隔离。若不支持已确认体验，应记录具体阻碍并重新讨论适配路径，不能静默改成框架自建审批界面。
2. 定义核心契约，以模拟 Agent 完成两类任务及检查、交付生命周期；通过真实本地文件与 Git remote 验证证据和恢复。
3. 接入单实例服务端与 MySQL、客户端 SQLite、HTTP 长轮询、结果去重和文件产物，验证依赖、失败传播、认证及断网与重启。
4. 接入真实 Codex，完成本地原生交互和两类任务的端到端验收，提供独立入口、嵌入示例与使用说明。

Codex 的 [官方 app-server 文档](https://learn.chatgpt.com/docs/app-server)提供结构化协议与原生终端连接方式，实际支持范围应按目标版本确认。当前本机 Node.js 24.15.0 的 [内置 SQLite](https://nodejs.org/download/release/v24.15.0/docs/api/sqlite.html)为 release candidate，驱动兼容性需验证，存储接口保持独立于具体驱动。

## 首版范围外

动态 AI 规划、定时或周期调度、团队账户与多服务端实例协调、系统常驻安装、Windows 原生支持、Codex App 接管承诺、Agent 调用框架接单方案、PR/MR 创建、自动审批、自动跨机器接管执行、自动清理与无限修复循环。
