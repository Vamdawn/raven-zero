# TypeScript Coding 规则

适用于本仓手写 TypeScript 及测试。[Google 指南](https://google.github.io/styleguide/tsguide.html)是风格依据；下列“项目适配”结合[已确认技术方案](../design/technology-stack.md)，优先于上游的环境约定。来源版本及取舍见[调研记录](../research/coding-guidelines.md)。

## 执行顺序

1. 读取涉及模块的配置、公开入口和已有代码；确认修改范围及本文件适用规则，再开始编辑。
2. 修改完成后逐项检查命名、模块、类型及异步边界；例外必须在最小范围说明依据。
3. 从现有脚本确定检查命令，执行相关类型检查和测试；交付时报告实际结果与未验证项。仅修改文档时检查链接与差异，无需生成工程配置。

## Google 风格采用项

- 文件使用 `snake_case.ts`；类型、接口、类用 `UpperCamelCase`，函数、属性、变量用 `lowerCamelCase`，全局常量用 `CONSTANT_CASE`。接口名表达职责，不加 `I` 前缀。
- 使用具名导出；外部库要求时才用默认导入。只导出实际使用的符号；可变状态通过接口访问。
- 用模块函数组织工具能力；用 ESM 组织文件，第三方兼容之外不使用 `namespace`。
- 默认 `const`，重赋值用 `let`；使用对象与数组字面量、严格相等比较、普通单引号字符串和语句分号。
- 手写对象结构用 `interface`；联合、元组及类型运算用 `type`。局部显然类型交给推导，可选属性用 `?`。
- 未知值用 `unknown` 并收窄；对象字面量用类型注解校验，断言使用 `as`。断言和非空断言需要证据。
- 不重新赋值的字段标记 `readonly`；抛出 `Error`；JSDoc 解释契约而不重复 TypeScript 类型。

## 项目适配

### 模块与生成代码

- 包内相对导入带 `.js`，跨包走公开入口；纯类型使用 `import type` / `export type`。这是 Node ESM 发布约定，对 Google 的可选类型导入作了收紧。
- 生成的 Codex 协议类型保留上游命名和生成方式；需要领域命名时在适配边界映射。第三方配置文件使用工具要求的名称，不为风格重命名现有文档。
- 在配置尚未落地时，手写源码使用两空格缩进；这是仓库格式选择，不把 Google 示例的排版当作规范条款。后续格式配置的调整须同步本规则。

### 类型与契约

- 编译配置开启 `strict`；公开函数、公开方法及存储接口明确参数和返回类型，局部函数允许推导。
- Zod 契约推导出的 `type`、已有类型的派生结果是 `interface` 偏好的例外；遵循契约唯一来源，不另写重复结构。JSON 状态优先用契约中的字符串联合；手写代码不使用 `const enum`。
- HTTP、Agent、文件解析及数据库数据在边界校验和映射后进入核心。断言不能替代运行时校验；数据库 `null` 与协议字段缺失分别按契约处理。
- `any`、双重断言及非空断言仅限有证据的兼容边界或测试替身，并说明原因；优先用小接口和可校验的数据构造测试。运行时非法输入测试直接通过接收 `unknown` 的边界传入。
- 生产代码保持类型检查有效；`@ts-expect-error` 仅用于验证类型拒绝的测试，并注明预期错误。修复其他类型错误，不用 `@ts-ignore` 或 `@ts-nocheck` 隐藏它们。

### 异步与错误边界

- 每个 Promise 都有负责人：等待、返回或接入明确管理的后台任务；后台任务必须处理失败和结束，调用方能观察其状态。
- 捕获外部异常时先按 `unknown` 处理；转换为 `Error` 时保留原因。只捕获需要转换、恢复或补充上下文的操作；恢复失败不能报告成功。
- 对公开接口说明副作用、失败语义及资源所有权；异步接口额外说明取消和完成的区别。复用设计中的状态与恢复约定，不在风格规则中另定义状态机。

## 完成标准

每个改动的公开符号和外部输入都有明确类型或校验路径；没有未经说明的类型逃逸；每个新增异步分支的失败可观察。检查结果与例外均能由改动或交付记录核对。
