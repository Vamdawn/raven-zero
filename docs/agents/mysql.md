# MySQL Coding 规则

适用于服务端 MySQL 表、迁移及 Kysely/mysql2 存储实现；客户端 SQLite 按其独立方案处理。[阿里巴巴黄山版手册](https://github.com/alibaba/p3c/blob/6c59c8c36ecd8722c712d5685b8c3822c1c8b030/Java开发手册(黄山版).pdf)第五章提供建表、索引和 SQL 的依据；以下规则经过 MySQL 8.4 与 TypeScript 工具链适配。来源、版本差异及未采用项见[调研记录](../research/coding-guidelines.md)，资源所有权与迁移入口遵循[技术方案](../design/technology-stack.md)。

## 执行顺序

1. 读取当前迁移、查询和存储映射；列出本次涉及的字段语义、唯一性、访问路径及并发条件，再设计变更。
2. 修改结构和查询时同步检查结果映射、索引及恢复路径；每个新增业务唯一键或状态写入都有数据库层保障。
3. 用真实 MySQL 8.4 验证受影响行为；高频或可能扫描大量数据的查询检查执行计划。记录实际结果、适用数据规模及未验证项。

## 建表与数值

- 表、列采用小写 `snake_case`，实体表名用单数，避开保留字；框架表前缀按既定方案。唯一索引用 `uk_`、普通索引用 `idx_` 加用途名；主键名称为 MySQL 的 `PRIMARY`，不套用手册的 `pk_`。
- 使用 InnoDB；每张表明确主键。主键类型按领域标识和访问路径确定，不因手册示例将已有任务标识改成自增整数。
- 布尔列用 `is_xxx TINYINT UNSIGNED`，限定为 0/1，在存储边界映射为 boolean；Java POJO 的命名限制不适用 TypeScript。
- 默认字段 `NOT NULL`，默认值必须有业务含义；只有“缺失”本身有意义时允许 NULL，并在映射中保留该语义。幂等唯一键明确非空条件，不能依赖 UNIQUE 阻止多个 NULL。
- 表及连接使用 `utf8mb4`；标识符、令牌等精确匹配字段明确 collation，使比较与唯一约束符合契约。
- 长度按实际范围选择；固定长度文本可用 CHAR，变长文本用 VARCHAR。精确小数用 DECIMAL，整数范围按上限选择；禁止用 FLOAT/DOUBLE 保存精确金额。
- 有创建/更新生命周期的表使用 `create_time` / `update_time`，更新数据时维护后者；这是新版手册命名，旧版 `gmt_*` 不混用。事件时间与生命周期时间分别表达。

## TypeScript 值映射

- Kysely 类型声明必须匹配驱动真实返回值；它不执行运行时转换。数据库行类型留在存储模块，显式映射成核心数据。
- DECIMAL 保持精确表示；mysql2 设置 `supportBigNumbers: true` 与 `bigNumberStrings: true`，使 BIGINT 等大整数稳定返回 string，并核对 COUNT 的结果类型。转换 number 前验证安全范围；精确小数不能仅经 Number 转换，`decimalNumbers: true` 不能作为精确计算方案。
- 时间统一 UTC，明确列类型、精度、会话时区及驱动转换策略。DATETIME 不保存时区；TIMESTAMP 按会话时区转换且有 2038 上限，两者均不保留原时区名。需要原时区时单独记录。
- 使用真实数据库往返验证 boolean、NULL、Unicode、大整数、精确小数及时间；样例值必须覆盖超出 JavaScript 安全整数范围和时区变化。

## 索引与查询

- 业务唯一性及结果去重用完整业务键的 UNIQUE 约束保障；重复键错误按领域语义处理，不只靠“先查再插”。唯一前缀索引只约束前缀，不能代替完整标识唯一性。
- 根据 WHERE、JOIN、ORDER BY 的真实访问路径设计组合索引，注意最左前缀；关联列类型一致。避免冗余索引，并用 EXPLAIN 核对索引选择及扫描范围。
- 索引长度按字符集、页大小和行格式核对；不固定所有 VARCHAR 为 191，也不对所有文本索引自动截取前缀。
- 明确 SELECT 列及别名，写入只修改目标字段；分页有稳定排序和唯一的并列排序键。大列表优先游标分页，批量查询限定规模，避免无界深 OFFSET 和无界 IN。
- 谓词保持类型一致，避免对索引列施加隐式转换、无必要函数或前导通配符；确有需求时用执行计划说明代价。
- COUNT(*) 统计行，COUNT(col) 忽略 NULL；SUM 空集合返回 NULL。需要零值时显式 COALESCE；NULL 判断使用 IS NULL / IS NOT NULL。
- 值通过 Kysely 参数绑定或 mysql2 占位符传入；Kysely 的 `sql` 标签普通值插值是参数化入口。动态表名、列名和排序方向使用允许列表；`sql.raw/ref/id/table/lit` 等入口不接收未经验证的外部输入。

## 并发、事务与迁移

- 状态转换采用带预期状态或版本的条件 UPDATE，并检查影响行数；更新确实改变状态或版本，区分冲突、未找到及重复请求。需要读取后决策时评估事务锁定读，普通 SELECT 不代表已锁定。
- 事务只包含必要数据库操作，按一致顺序访问记录；网络、文件、Git 和 Agent 操作在事务外执行。死锁重试仅用于可安全重试的完整事务，并限定次数；外部副作用按设计核验和恢复。
- 每个关联说明如何保障引用完整性：外键约束或应用事务检查。外键删除行为明确评估；手册的禁用外键不升级成本仓默认禁令。
- 结构变更通过新迁移管理，只操作框架拥有的表；说明已有数据兼容、执行顺序及失败恢复。多数 DDL 和 TRUNCATE 会隐式提交，不能承诺整次迁移由一个事务回滚。
- 软删除、归档、分片及查询数量限制依据产品语义和实测决定；手册中的固定阈值不是自动建机制的依据。

## 完成标准

每个改动字段的空值、精度和时间语义可核对；每个业务唯一键、并发写入及关联完整性都有保障；迁移失败有明确恢复办法。相关查询、冲突和边界值已由真实数据库验证，或在交付中明确列为未验证。
